# 商业视觉生产 Skill V3.0.0

[English](README.en.md) · [验证范围 / Validation](VALIDATION.md) · [发布说明 / Release notes](CHANGELOG.md)

面向支持本地 Skill、文件操作、Python 和内置图像生成工具的助理环境，将参考解析、品牌转译、创意蓝图、视觉生产、核验、定向修复与 PNG/ORA 交付连接为可追溯流程。项目文件保存当前有效要求、素材、父子版本、问题与用户决定；恢复会话时重新读取状态，而不是依赖模型记住整个聊天。

技能名：`commercial-visual-production-v3-0-0`。当前版本：**3.0.0**。这是执行指引、项目状态程序、检测工具和本地审核工作台的组合，需要助理参与视觉理解与图像工具调用。

## 使用范围

适合商业海报、品牌活动主视觉、电商或社交视觉的单项目制作，以及需要明确基准、保留既有成果的连续返图。可按项目选择整图候选或分层生产；严格的产品、人物、Logo 与准确文字应使用真实原件或独立文字栅格层合成。

核心能力：

- 参考图九模块解析，并区分观察、估计和未知。
- 将参考特征与本项目品牌资产、用途、规范进行采用、改写或舍弃，防止未采用的参考内容进入制作。
- 从文字、草图或二者结合建立蓝图、布局、正式文案、保护对象与结构预览。
- 编译背景、独立素材、整图和局部编辑四类任务；自动在实际提示中加入适用的负面约束。
- 按当前规则、已选基准和本轮差异持续修改；保留来源、附件顺序、文件校验值及父子版本。
- 局部范围外的 RGBA 像素保护、接缝与目标达成复核、缺陷工单和具体版本的用户接受。
- 从冻结母版导出并重新读取 PNG/ORA，检查层序、透明度及重组一致性。

不应把该技能当作无助理的自动设计服务、原生 PSD/矢量/活文字编辑器、自动身份识别或自动 OCR 系统，也不提供印刷打样与专色认证。原始模型输出仍可能出现多余修改；最终采用图通过原件、选区、合成与检查控制。详细验证边界见 [VALIDATION.md](VALIDATION.md)。

## 环境与安装

运行脚本需要 Python 3.10 或更高版本，以及 Pillow、NumPy。SciPy 为可选项；区域内羽化可使用 Pillow 回退。图像生成需要当前对话提供内置 `image_gen.imagegen`，该首选路径不需要填写外部 API 密钥。普通 Python 或网页环境单独安装本仓库不能获得该工具。

1. 下载或克隆本仓库。
2. 将 `skills/commercial-visual-production-v3-0-0` 整个文件夹放入 `$CODEX_HOME/skills/`。未设置该变量时，常见目录为 `~/.codex/skills/`。
3. 在用于本技能的 Python 环境安装依赖：`python -m pip install -r requirements.txt`。
4. 打开新对话并调用 `$commercial-visual-production-v3-0-0`。旧 V2.3.0 可保留，但同一项目不要混用阶段语义。

支持 Skill 安装器的环境也可以从仓库中的 `skills/commercial-visual-production-v3-0-0` 路径安装。跨主机平台兼容性尚未全部实测；本轮实测环境为 Windows。

建议的起始请求：

> 使用 $commercial-visual-production-v3-0-0，为本项目依次完成参考解析、品牌转译、蓝图与视觉生产。先读取我提供的参考和品牌资产，缺少关键资料时再问我；生成前让我确认蓝图，返图仅修改明确范围，最终交付 PNG 和 ORA。

用户不需要手写内部 JSON。助理根据真实素材和用户说明建立项目记录，只追问影响执行的缺项。

## 开始前提供什么

- 参考图片及每张的角色：风格、布局、材质或其他借鉴用途。
- 品牌标识、产品或人物原件、已有品牌视觉文件，以及使用权限由项目方自行确认的素材。
- 使用场景、画布比例或尺寸、品牌规范、准确文案、必须保留或禁止出现的内容。
- 创意文字、草图或混合输入；进入 R3 前补充素材描述和海报注意事项，已经提供的内容直接继承。
- 修改任务需明确基准；存在多个候选且指代不清时才补问。

## 完整生产与交付流程

| 阶段 | 输入与执行 | 输出及进入下一步的条件 |
| --- | --- | --- |
| R0 参考解析 | 查看真实参考图，分析视觉风格、设计排版、素材处理、色彩、字体文字、光影材质、空间关系、图形装饰、视觉机制综合九模块 | 有证据的观察、估计与未知；此时不替本项目制作蓝图 |
| R1 品牌转译 | 读取 R0、品牌资产、用途及规范，逐项采用、改写或舍弃；记录来源、范围和替代关系 | 当前有效品牌要求；参考品牌、人物或文案不会自动成为本项目内容 |
| R2 创意与蓝图 | 接收文字、草图或混合创意，整理布局、层次、文案、原件、保护项和结构预览 | 可执行蓝图；解决关键冲突，取得针对该蓝图版本的用户确认 |
| R3 视觉生产 | 读取有效 R1/R2、素材描述和注意事项，选择整图或分层，编译任务并校验实际图片与提示 | 实际原图、采用候选、调用记录、图层更新及校验值；排队或编译不能冒充已生成 |
| R4 结果核验 | 读取实际候选，对照当前要求、原件与蓝图；执行适用检测，并记录助理的视觉观察 | 绑定该版本的报告与 P0/P1/P2 问题；未知项不能记为通过 |
| R5 修复与冻结 | 从明确基准创建最小修改任务，回到 R3，再进入 R4；同时检查本轮目标、以前成果和非目标区域 | 通过核验且用户接受的具体候选，可冻结为母版；无缺陷时无需制造修复轮次 |
| R6 交付验收 | 从有效冻结母版导出 PNG/ORA，重新读取图层，核对尺寸、层序、透明度、文件校验值和重组结果 | PNG、栅格 ORA、源图层及报告；用户对具体交付版本作最终验收 |

默认用户确认集中在三处：**确认蓝图、接受候选、验收交付**。用户明确提出的新修改已经授权该范围；只有实际冲突、关键缺失或多版本指代不清时补问。自动检测、助理视觉判断与用户决定分别记录。本地决定记录不是认证签名。

## R3 如何继承意图

每次实际调用重新组织当前必需信息：任务与用途 → 实际图片角色 → 画面层级与相对位置 → 有效要求和准确内容 → 本轮变化与此前成果 → 注意事项及内置禁止事项 → 输出及验收条件。图像模型无需理解内部 R0–R6 编号。

程序阻止过期规则、不明确基准、缺失或错序附件、未确认蓝图、未解决关键冲突及局部范围缺失的相关执行。助理负责语义解释、同义去重与真实视觉判断，结构检查不冒充语义理解。长期要求保存在项目要求中，本轮备注不代替它们。

实际 AI 入口为内置 `image_gen.imagegen`。用户可能称其为 ChatGPT Image 2.5，但公开工具未提供后台型号选择，不能据此验证具体模型版本。禁止事项进入真实 `prompt`；没有虚构的 `negative_prompt`、seed、CFG、steps 或 mask 接口。用户明确需要的颗粒、笔触等效果不会被通用禁令无依据地删除。

## 连续修改与最小改动

每轮绑定父版本、当前有效要求、本轮差异、允许修改区、过渡区、保护区和真实输入输出。当前工作版与已接受版分开，新候选不会自动替换接受版；选择旧版继续会保留分支历史。新要求只替换其涉及范围的旧要求，舍弃项不得重新回流。

优先修正源文字栅格层、原件层或合成参数；确需生成时才创建相应任务。局部硬锁要求同尺寸、同坐标，范围外与基准 RGBA 完全相同；尺寸或对齐不符时停止，不静默缩放。目标达成、接缝自然和历史修改保留仍须独立检查。

修复层为可追溯的栅格补丁，不能宣称自动重建完整独立背景或原生对象。精确坐标保存在制作计划，提示只保留必要位置语言，避免每轮重复聊天全文；完整证据留在项目，恢复会话仍读取当前权威状态。字符减少不等于已测得相同百分比的计费 Token 节省。

## 审核按钮与缺陷闭环

本地工作台可查看有效要求与来源、运行检查、读取报告、登记用户决定、提交问题、创建定向修复、提交复核、比较版本及选择旧版继续。运行检查真正产生新报告；查看报告只读取并检查时效。生产按钮仅登记 `waiting_execution`，须由当前对话助理调用图像工具。

缺陷流程为：待修复 → 修复中 → 待复核 → 核验关闭；失败或证据失效须重新处理。P0/P1、关键未知和必要证据缺失阻止冻结；具体非关键 P2 只有用户明确接受该版本的问题才可保留，接受不代表修复。

## 交付物与验收

| 交付物 | 含义 |
| --- | --- |
| `merged_preview.png` | 从批准母版导出的最终栅格合成图 |
| `layout_layers.ora` | 平面 src-over 图层栈，可保存源栅格层与局部补丁；不是可编辑 PSD |
| 源图层与制作规格 | 用于重组的真实文件、布局及图层来源 |
| 核验与差异报告 | 实际执行的检查、修改区外及保护区比较、已知限制 |
| 项目记录与版本证据 | 当前要求、父子版本、任务、问题、接受及交付决定 |

项目资料保存在项目目录，是否向客户分享历史、原件或内部证据由项目方决定。最终候选、核验对象和导出母版必须是同一有效版本。目标设计软件的实际打开兼容性需另行验证；未测软件不得标为兼容。

## 脚本、工作台和测试

通常由助理执行。以下命令在 `skills/commercial-visual-production-v3-0-0` 内运行：

```sh
python scripts/workflow.py init --project <project-directory> --project-id <project-id> --call-budget 4
python scripts/stage_context.py build --project <project-directory> --stage R3
python scripts/start_review.py --project <project-directory> --port 8765
python -m unittest discover -s tests -q
```

兼容测试需在独立进程、独立目录运行，避免旧模块污染新流程：

```sh
cd compat/v2
python -m unittest discover -s tests -q
```

## 版本与旧项目迁移

V3 使用 `cvisual.workflow.v3` 项目状态。复用检测报告保留 `cvisual.audit.v2` 与 `tool_version=2.2.0`，它们是独立报告协议号，不代表安装了旧包。

旧参考解码 → R0；旧品牌资产与用途 → R1；旧蓝图及预览 → R2；旧生产与保护 → R3/R5；旧成品质检 → R4；旧交付检查 → R6。迁移默认预演，应用时写入全新目录，原项目不改。旧批准不能自动成为新批准，旧“已提交修复”也不能冒充核验关闭。
