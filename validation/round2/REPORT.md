## 原生中文修复证据

此案例使用公开中文短说明和确定性字体栅格层；背景适配器返回是明确标记的模拟图，真实图像工具调用为 0。

1. 注入错字候选被记录为 P1，req:copy 为 FAIL。
2. 修复计划继承实际基准 spec，保留 materialize 写入的描述及既有层结构；早期准备脚本遗漏该描述，被现有结构检查正确拒绝，随后修正了准备脚本。
3. prepare-source 只替换 headline-raster；增加模拟 begin 事件 0。
4. 修改区内变化 1,384 像素；区外 0；保护区 0；图层可精确重组。
5. 助理查看保存的前后图，记录目标、历史、接缝、设计和准确文案观察，再 verified_closed。
6. QC PASS；accepted_revision 仍为空，user_visual_acceptance=NOT_PROVIDED。没有把助理观察写成用户商业接受。

另一个保留的 64×96 流程夹具包含四个模拟 begin 事件及测试接受/冻结/交付决定，用于验证状态闭环。该计数不代表四次真实图像调用。

## 复现与后续

程序回归：
    python tools/run_validation.py --out <new-evidence-directory>

生成八层原生测试文件：
    python tools/prepare_validation_samples.py --out <new-directory> --font <CJK-font-file> --samples <public-sample-directory>

    python tools/prepare_validation_project.py --out <new-directory>

    python tools/prepare_zero_call_cases.py --out <new-directory> --samples <native-sample-directory> --font <CJK-font-file>
